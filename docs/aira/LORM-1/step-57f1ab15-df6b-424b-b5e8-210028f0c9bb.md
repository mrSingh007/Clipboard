# Product Specification: Fix Delete Icon Confusion in Clipboard History

## Problem Statement
In the Clipboard History app (dark theme), when a user hovers over any clipboard history item, two action buttons appear on the far right: **Pin** and **Delete**. The Delete button uses a trash can icon (16×16px SVG) rendered in a muted gray color (`--text-tertiary: #707070`). At this small size and low contrast, the trash can icon resembles a clipboard/document icon. Users click it expecting to copy the item, but the item is immediately deleted with no confirmation.

**Impact**: Accidental data loss with no recovery. The primary action (clicking the item body) copies to clipboard; Delete is a destructive secondary action that should be unmistakable.

## Intended Outcome
Users can clearly distinguish the Delete action from Copy/Pin actions. Accidental deletions are prevented or require explicit confirmation. The visual language makes destructive actions obvious at a glance.

## What Will Change

### 1. Delete Icon Replacement (Visual)
- **Where**: Clipboard history list → each item's action buttons (far right on hover)
- **Change**: Replace the trash can SVG with a distinct "X" icon (cross mark) that is unambiguously "delete/remove" and cannot be confused with a clipboard.
- **Before**: Trash can icon (polyline + path forming a bin shape)
- **After**: Simple "X" mark (two crossing lines) — universally recognized as delete/close/remove

### 2. Delete Button Visual Distinction (Visual)
- **Where**: Same delete button in the item actions area
- **Change**: Apply a subtle red tint to the delete button **by default** (not only on hover), using the existing `--accent-danger` color token. This makes it visually distinct from the Pin button (amber) and the item body (neutral).
- **Before**: Muted gray icon (`--text-tertiary`), red tint only on hover
- **After**: Subtle red background/border or red icon color at rest; stronger red on hover

### 3. Confirmation Before Deletion (Interaction)
- **Where**: Clicking the Delete button
- **Change**: Show a native confirmation dialog: "Delete this clipboard item? This cannot be undone." with **Cancel** (default) and **Delete** buttons.
- **Before**: Immediate deletion on click
- **After**: Deletion only after explicit confirmation

### 4. Tooltip on Hover (Accessibility)
- **Where**: Delete button
- **Change**: Add a tooltip (native `title` attribute or custom tooltip) reading "Delete item" so users can verify the action before clicking.
- **Before**: No tooltip; only `aria-label="Delete item"` for screen readers
- **After**: Visible tooltip on hover for all users

## User Experience: Before vs. After

| Scenario | Before | After |
|----------|--------|-------|
| User hovers a pinned item | Two gray buttons appear; rightmost looks like clipboard | Two buttons appear; rightmost is a red-tinted "X" with "Delete item" tooltip |
| User clicks rightmost button | Item vanishes immediately | Confirmation dialog appears; user must confirm |
| User realizes mistake | No undo; item lost | Can click Cancel in dialog |
| Screen reader user | Hears "Delete item" | Same, plus visual cues for sighted users |

## Scope

### In Scope
- Replace delete icon SVG in the item template (`index.html`)
- Update delete button styling in `style.css` (default red accent, hover state)
- Add confirmation dialog in `renderer.ts` delete handler
- Add tooltip/title attribute to delete button

### Out of Scope
- Changing the Pin icon or behavior
- Changing the primary copy action (click item body)
- Adding an undo toast/notification after deletion (could be a follow-up)
- Keyboard shortcut for delete (currently none)
- Mobile/touch considerations (desktop-only app)
- Light theme adjustments (issue reported for dark theme; changes should work in both)

## Acceptance Criteria

1. **Icon clarity**: In dark theme, at 100% zoom, a user unfamiliar with the app can identify the delete button as "delete/remove" (not "copy") within 2 seconds of hovering an item.
2. **Visual distinction**: The delete button shows a red accent (icon color or background) in its resting state on hover, clearly differentiated from the Pin button (amber) and non-action areas.
3. **Confirmation required**: Clicking the delete button shows a native confirmation dialog with "Delete" and "Cancel" options. The item is only deleted if "Delete" is chosen.
4. **Tooltip visible**: Hovering the delete button for >500ms shows a "Delete item" tooltip.
5. **No regression**: Pin button continues to work; clicking item body still copies to clipboard; keyboard navigation (Enter to copy) unchanged.
6. **Accessibility**: `aria-label="Delete item"` preserved; focus states unchanged; confirmation dialog is keyboard-accessible.

## Unresolved Decisions / Clarification Questions

1. **Icon choice**: "X" mark is proposed. Alternatives: more detailed trash can with lid, or a "minus in circle" icon. Team preference?
2. **Confirmation wording**: "Delete this clipboard item? This cannot be undone." — approve or suggest alternate text?
3. **Red accent implementation**: Icon color only? Background tint? Border? (Recommendation: icon color = `--accent-danger` at rest; background tint on hover)
4. **Pinned vs. unpinned**: The ticket mentions pinned items specifically. Should pinned items have additional protection (e.g., double confirmation)? Currently the code treats them identically for delete.
5. **Undo capability**: Out of scope now, but should we track as a follow-up? (e.g., toast with "Undo" for 5 seconds after deletion)

## Assumptions
- The delete icon appears for **all items on hover**, not just pinned items (per current CSS lines 599–604). The fix applies universally.
- The app is macOS-only (per package.json), so native `confirm()` dialog is acceptable.
- No telemetry/analytics to measure accidental deletion rate; acceptance criteria are qualitative.
- Dark theme is the primary concern; changes must not degrade light theme.
