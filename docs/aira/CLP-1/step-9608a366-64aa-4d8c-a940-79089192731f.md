# Ticket CLP-1 – Max items feature

## Goal

Limit the number of **unpinned** clipboard entries to **20**. When a new entry is added and the limit is exceeded, the oldest unpinned entry should be automatically removed. **Pinned** entries must never be removed, regardless of the limit.

## Why this change

- Keeps the history list small and fast to browse.
- Prevents the SQLite file from growing unnecessarily.
- Matches the user‑requested behaviour of a fixed maximum for normal items while always preserving important (pinned) items.

## What will change

1. **Default setting** – The built‑in default for "Maximum unpinned items" will be changed from 1 000 to **20**.
2. **User interface** – The drop‑down in the Settings panel will get a new option for **20** items, and it will be pre‑selected because it matches the new default.
3. **Validation** – The existing validation already allows any integer from 0 to 10 000, so no change is needed there.
4. **Automated tests** – The test that checks the default settings will be updated to expect `maxItems: 20` instead of `1000`.
5. **Documentation** – The README or any user‑facing docs that mention the default history limit will be updated to reflect the new 20‑item default.

## How we will do it (high‑level steps)

1. **Change default value**
   - In the settings file where defaults are defined, replace the line that sets `maxItems: 1000` with `maxItems: 20`.
2. **Add 20‑item option to the UI**
   - Edit the HTML that builds the Settings panel (the `<select id=\"setting-max-items\">` element). Insert a new `<option value=\"20\">20</option>` near the top of the list.
   - Because the JavaScript already sets the select’s value from the stored setting, the new default will automatically appear selected.
3. **Update the test expectation**
   - In the test suite that verifies the default settings, change the expected object to contain `maxItems: 20`.
4. **Run the full test suite**
   - Execute `npm test` to make sure all existing tests still pass and the new expectation works.
5. **Manual verification**
   - Start the app, open Settings, confirm that the “Maximum unpinned items” field shows **20**.
   - Copy more than 20 different pieces of text and verify that the oldest unpinned entry disappears while any pinned entries stay.
6. **Update documentation**
   - Adjust any mention of the default history size in the README or help screens to state the new limit of 20.

## Acceptance criteria

- The default value in a fresh install is **20**.
- The Settings dropdown lists an option for **20** and selects it by default.
- Adding the 21st unpinned item causes the 1st unpinned item to be removed automatically.
- Pinned items are never removed, even when the limit is reached.
- All automated tests pass after the changes.
- The documentation accurately reflects the new default.

## Risks & Mitigations

- **Risk:** Existing users may have a different limit saved in their settings.
  - **Mitigation:** The change only affects the default for new installations; existing users keep whatever value they already have.
- **Risk:** UI may not show the new option if the HTML is regenerated during build.
  - **Mitigation:** Verify the built `renderer.js` includes the new option by running a quick manual test.

## Deployment notes

- No database migration is required because the pruning logic already works for any limit.
- The change is completely backwards compatible – users who set a higher limit themselves can still do so.
- After release, monitor crash reports for any unexpected behavior when the history limit is applied.
