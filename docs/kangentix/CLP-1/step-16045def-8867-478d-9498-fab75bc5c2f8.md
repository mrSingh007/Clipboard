# Dark / Light Theme Manual Switch

## Problem
- The application automatically follows the macOS system appearance. When the OS is set to dark mode, the Clipboard History window is always dark.
- Users cannot manually change the appearance; there is no control in the UI.
- This makes it difficult for users who prefer a light interface even when their system is dark.

## Intended Outcome
- Provide a simple control that lets users choose between light and dark mode from within the app.
- The chosen appearance should be applied immediately and remembered for future sessions.
- The control should be located in the Settings panel, where other preferences are already managed.

## What Will Change
- **Settings Panel**: A new “Appearance” section will be added (or a toggle will be placed within the existing “General” section). It will contain a labeled switch (e.g., “Dark mode”) or a two‑state button.
- **User Interface**: When the switch is toggled, the colors of the whole application (main window, settings panel, list items, etc.) will change instantly.
- **Persistence**: The selected mode will be saved so that the app opens in the same appearance the next time it’s launched.

**Where Users Will Notice It**
- Clicking the gear icon opens the Settings panel; the new toggle will be visible near the existing checkboxes.
- After toggling, the background, text, and UI elements change throughout the app.
- The next time the user starts Clipboard History, it starts in the previously chosen mode rather than following the OS.

## Before and After
| Situation | Current Behavior | After Change |
|-----------|-----------------|--------------|
| macOS set to dark mode, app opened | App always appears dark, no option to change | User can press the new “Dark mode” toggle to switch to light (or turn on dark if the default was light). |
| macOS set to light mode, app opened | App appears light | User can press the toggle to switch to dark. |
| User changes toggle and closes app | N/A | When the app is reopened, it remembers the last selected appearance and starts in that mode. |

## Scope
### Included
- UI element (toggle/button) in Settings for selecting Light or Dark mode.
- Immediate visual update when the toggle is changed.
- Saving the user’s choice and restoring it on app start.
- Documentation in the Settings UI (e.g., tooltip or short description) explaining the purpose of the toggle.

### Excluded
- Additional theme options (e.g., custom colors, high‑contrast theme beyond what the OS already provides).
- An explicit “Follow system” option if the toggle is off (the app will still follow the OS when the setting is not set; this behavior will be clarified if needed).
- Changes to the tray icon or macOS dark‑menu‑bar handling beyond the automatic CSS support already present.
- Localization of the new toggle label (outside the current English UI).

## Acceptance Criteria
1. **Visible Control** – The Settings panel shows a clearly labeled control (e.g., a switch named “Dark mode”) for theme selection.
2. **Immediate Theme Switch** – When the user toggles the control, the entire UI updates to the opposite theme within a second.
3. **Persistence** – After closing and reopening the app, the UI starts in the theme that was last selected via the toggle.
4. **Correct Default** – If the user has never changed the appearance, the app follows the system theme (i.e., no forced mode is applied).
5. **No Side‑Effects** – All existing functionality (clipboard monitoring, shortcuts, history actions) continues to work unchanged.
6. **Accessible** – The new control can be reached and operated with keyboard navigation and has appropriate ARIA labels.

## Assumptions
- The toggle will be a simple binary switch: **On = Dark mode**, **Off = Light mode**. When the switch is off, the app will use the light theme regardless of the OS setting (unless we decide to add a “System” option later).
- The chosen theme is stored in the same key‑value store used for other preferences, so it survives app restarts.
- Users expect the theme to change instantly; no app restart should be required.

## Open Questions / Clarifications Needed
1. **Toggle Behavior** – Should the toggle be a binary “Dark mode” switch (dark/light) or a three‑state control that also offers “Follow system”?
2. **Default State** – If the user has never opened Settings, should the app default to “Follow system” or to a specific theme (e.g., light)?
3. **Labeling** – Preferred wording for the control: “Dark mode”, “Use dark theme”, “Appearance: Dark/Light”, or something else?
4. **Persistence Location** – Do we need to expose the new setting in any exported configuration file, or is it sufficient to keep it internal to the app?

Please provide direction on the above points so the design can be finalized.
